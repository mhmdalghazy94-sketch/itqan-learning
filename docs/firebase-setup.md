# إعداد Firebase لموقع إتقان

يستخدم الموقع إعداد Web App الخاص بمشروع `itqan-learning` في `src/js/services/firebase.js`، ويحمل Firebase JavaScript SDK modular من CDN. لا حاجة إلى تطبيق هاتف أو npm لهذا الإعداد.

## نشر الموقع والقواعد عبر Firebase CLI

أُضيف `firebase.json` لإعداد Hosting على ملفات الموقع الثابتة في جذر المشروع، مع استبعاد وثائق التطوير والأدوات والقواعد من الملفات المنشورة. يشير `.firebaserc` إلى المشروع `itqan-learning`.

بعد تثبيت Node.js، افتح PowerShell من مجلد المشروع ونفذ:

```powershell
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```

تحقق من نجاح نشر القواعد قبل نشر الموقع. بعد ذلك انشر ملفات الويب:

```powershell
firebase deploy --only hosting
```

سيعرض CLI عنوان `https://itqan-learning.web.app` عند توفر موقع Hosting الافتراضي. أضف `itqan-learning.web.app` إلى **Authentication → Settings → Authorized domains** إذا لم يظهر تلقائيًا. لا تنفذ أمر النشر من مجلد مختلف عن جذر المشروع.

## الإعداد الأولي في Firebase Console

1. افتح المشروع `itqan-learning` وتأكد من تسجيل Web App في إعدادات المشروع.
2. في **Authentication → Sign-in method** فعّل **Email/Password**.
3. في **Authentication → Settings → Authorized domains** أضف `127.0.0.1` و`localhost` للتطوير إن لم يكونا موجودين. أضف نطاق الموقع المنشور لاحقًا، دون البروتوكول أو المسار أو المنفذ.
4. أنشئ قاعدة **Cloud Firestore** في وضع الإنتاج واختر المنطقة المناسبة؛ موقع قاعدة البيانات لا يمكن تغييره بعد إنشائها.
5. انشر محتوى `firestore.rules` بالأمر أعلاه أو من **Firestore Database → Rules**. لا تستخدم قواعد تسمح بالقراءة والكتابة العامة.
6. قد يلزم إعداد قالب رسالة التحقق وإعادة تعيين كلمة المرور في **Authentication → Templates**. اختبر البريد من نطاق مصرح به.

## إعداد روابط البريد على GitHub Pages

للموقع الحالي أضف `mhmdalghazy94-sketch.github.io` إلى **Authorized domains**. إعدادات Firebase في الشيفرة تولّد روابط متابعة إلى:

- `https://mhmdalghazy94-sketch.github.io/itqan-learning/pages/welcome.html` للتحقق من البريد.
- `https://mhmdalghazy94-sketch.github.io/itqan-learning/pages/reset-password.html` لإعادة تعيين كلمة المرور.

لاستخدام صفحات الموقع لمعالجة الروابط، خصص **Action URL** لكل قالب في **Authentication → Templates**:

- قالب إعادة تعيين كلمة المرور: `https://mhmdalghazy94-sketch.github.io/itqan-learning/pages/reset-password.html`
- قالب التحقق من البريد الإلكتروني: `https://mhmdalghazy94-sketch.github.io/itqan-learning/pages/verify-email.html`

لا تضف `mode` أو `oobCode` يدويًا؛ يضيفهما Firebase إلى الرابط، وتعالج الصفحة الرمز عبر Firebase ثم تحذفه من شريط العنوان. المعالج الافتراضي في Firebase لا يمرر رمز إعادة التعيين إلى صفحة الموقع بعد إتمام العملية؛ لذلك لن يعمل نموذج `reset-password.html` المخصص ما لم تضبط Action URL للقالب كما سبق. أما `url` في إعدادات JavaScript فهو رابط متابعة، وليس بديلًا عن Action URL المخصص.

GitHub Pages يستضيف الملفات الثابتة فقط. ملفات Firebase المطلوبة يجب أن تكون منشورة في الفرع/المجلد الذي يخدمه Pages؛ تغييرات مجلد العمل المحلي لا تظهر في الموقع حتى تُرفع إلى GitHub.

## التحقق من التسجيل

- حساب الطالب يُنشأ في Firebase Authentication ويُحفظ ملفه في `users/{uid}` بدور `student`.
- حساب المعلم يُنشأ بحالة `pending`، وقواعد Firestore تمنع المستخدم من تعديل الدور أو الحالة. لا تمنح صلاحية معلم قبل مراجعة موثوقة وتغيير الحالة من جهة إدارية/خادم موثوق.
- يتطلب تسجيل الدخول تأكيد البريد. التحقق من عنوان صفحة الويب أو إخفاء رابط ليس بديلًا عن قواعد Firestore عند حماية البيانات.
- لا يُحمّل Analytics رغم وجود `measurementId` في الإعداد، التزامًا بعدم تفعيل تتبع غير مطلوب.

## حدود لوحة المعلم وصفحات التواصل والسياسات

- `pages/teacher/dashboard.html` وصفحات إدارة الدورات والواجبات تتحقق من حساب معلم موثق ونشط. فرض ملكية البيانات موجود أيضًا في قواعد Firestore؛ فإخفاء الصفحة أو عناصرها ليس حدًا أمنيًا.
- قاعدة `firestore.rules` تدعم حاليًا بيانات الدورات المجانية، التسجيل الذاتي في دورة منشورة، الواجبات النصية، المسودات، التسليم النهائي، والتصحيح. تفاصيل الاستخدام والقيود موضحة في قسم **سير عمل الدورات والواجبات** أدناه.
- لوحة الطالب تتحقق من هوية الطالب وبريده ودوره قبل العرض. صفحات الطالب الأخرى التي تستخدم `student-mock.json` موسومة بوضوح كبيانات تجريبية؛ لا تمثل حساب المستخدم ولا تحفظ بياناته. لوحة الطالب الرئيسية لا تعرض هذه العينات.
- نموذج `pages/site/contact.html` لا يرسل ولا يحفظ الرسائل حتى إعداد نقطة استقبال موثوقة وقواعد حماية للبلاغات والمرفقات. لا تستخدمه لاستقبال بيانات فعلية قبل ذلك.
- صفحات السياسات داخل `pages/legal/` مسودات معلوماتية وليست شروطًا نهائية. استكمل بيانات الجهة المشغلة، القانون المختص، وسائل التواصل، مدد الاحتفاظ، تفاصيل الدفع والاسترداد، ثم راجعها قانونيًا قبل نشرها كسياسات نافذة.
- دليل المكتبات وصفحات العلوم لا تعرض روابط مستودعات أو أعداد محتوى غير متحقق منها. أضف عناوين المستودعات الحقيقية بعد إعدادها واختبار صلاحية النشر.

إذا ظهرت `auth/configuration-not-found`، فعّل مزود **Email/Password**. وإذا رفض Firestore الاتصال أو لم توجد قاعدة، أنشئ Cloud Firestore وانشر قواعد `firestore.rules`.

## سير عمل الدورات والواجبات

قبل فتح صفحات العمل، انشر القواعد الحالية من مجلد المشروع:

```powershell
firebase deploy --only firestore:rules
```

الصفحات الحالية:

- `pages/teacher/courses.html`: ينشئ المعلم النشط دورة باللغة العربية كمسودة، يضيف دروسًا نصية مرتبة، ثم ينشرها لتظهر في قائمة الدورات المجانية.
- `pages/teacher/assignments.html`: ينشئ واجبًا لدورة منشورة، وينشره، ويعرض التسليمات ويحفظ الدرجة والملاحظات.
- `pages/student/assignments/assignments-dashboard.html`: يتيح التسجيل الذاتي في دورة مجانية، ويعرض الواجبات المنشورة، ويحفظ المسودة تلقائيًا، ويثبت الإجابة نهائيًا بعد نجاح الكتابة وقراءة التأكيد من الخادم.

مخطط البيانات:

- `courses/{courseId}`: `ownerId`, `title`, `description`, `category`, `level`, `language`, `isFree`, `status`, `createdAt`, `updatedAt`.
- `courses/{courseId}/lessons/{lessonId}`: `ownerId`, `title`, `content`, `position`, `createdAt`, `updatedAt`. يستطيع مالك الدورة النشط إدارتها، ولا يقرأها الطالب إلا بعد التسجيل في دورة منشورة.
- `course_enrollments/{courseId--studentId}`: `courseId`, `studentId`, `createdAt`. يُسمح للطالب بإنشاء تسجيله فقط إذا كانت الدورة منشورة ومجانية.
- `assignments/{assignmentId}`: `courseId`, `teacherId`, `title`, `instructions`, `dueAt`, `maxScore`, `status`, `createdAt`, `updatedAt`.
- `assignments/{assignmentId}/submissions/{studentId}`: إجابة نصية حتى 20,000 حرف، حالة المسودة/التسليم، أوقات الحفظ، وحقول التصحيح التي لا يستطيع كتابتها إلا مالك الدورة النشط.

القواعد تمنع تعديل الطالب للدور أو الحالة، وتقيّد قراءة الواجبات والدروس بالطلاب المسجلين، وتمنع الطالب من تغيير إجابة بعد التسليم النهائي، وتسمح بالتصحيح ضمن الدرجة القصوى. تُقبل الإجابات المتأخرة وتُعلّم في واجهة المعلم؛ لا يوجد إغلاق تلقائي عند الموعد النهائي. الدروس نصية فقط، ولا تتضمن النسخة الحالية رفع ملفات، فيديو/صوت، تنظيم وحدات، اختبارات، إعادة تسليم، الحذف، إعادة التصحيح، الدفع، أو تقارير وتحليلات. لا تفعّل رفع الملفات قبل إعداد Firebase Storage ونشر قواعد Storage تمنع تجاوز الحجم أو النوع أو الملكية.

المعلم الجديد يبقى `pending` حسب سياسة التسجيل. تفعيل التدريس يجب أن يتم من جهة إدارية موثوقة بعد المراجعة، وليس من JavaScript العميل. لأغراض الاختبار يمكن للمشرف تغيير `status` إلى `active` في Firebase Console؛ للإنتاج استخدم عملية إدارية موثوقة وسجل التدقيق المناسب. لا تمنح وصولًا لحساب لا تملكه أو لم تتم مراجعته.

التنفيذ الحالي مناسب كبداية محدودة. قبل التوسع إلى أحجام كبيرة، أضف ترقيم صفحات ومؤشرات Firestore اللازمة واختبارات Emulator لقواعد القراءة والكتابة. لا توجد حاليًا خدمة خلفية لتصدير التقارير أو إرسال الإشعارات أو إنشاء الشهادات.

## التطوير والتحقق

شغّل الموقع عبر خادم HTTP محلي، مثل `python -m http.server 8000 --bind 127.0.0.1`، ثم افتح `http://127.0.0.1:8000`. لا تفتح HTML عبر `file://` لأن وحدات JavaScript وFirebase تحتاج أصل HTTP.

جرّب التسجيل بعنوان بريد تملكه، وافتح رسالة التحقق. لا تستخدم حسابات وهمية أو بيانات مستخدمين آخرين. بعد التسجيل تحقق من وجود وثيقة الملف الشخصي في Firestore ومن الدور والحالة. اختبر أن المستخدم لا يستطيع قراءة وثيقة مستخدم آخر أو تغيير `role` و`status`.

إعداد Web App و`apiKey` الذي يضمّنه الموقع مخصص للعميل وليس سرًا. لا تضع مفاتيح Service Account أو بيانات اعتماد Admin SDK أو مفاتيح Gemini في المستودع. حماية البيانات تعتمد على قواعد Firestore، لا على إخفاء إعدادات العميل.
