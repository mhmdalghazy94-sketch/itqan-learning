# خريطة مستودعات إتقان

## النطاق الموجود في مساحة العمل

هذا المشروع هو موقع البوابة الحالي، ويحتوي على الموقع العام ومصادقة Firebase وصفحات الطالب والمعلم ودليل المكتبات. الهيكل الحالي ينظم الصفحات داخل مستودع واحد:

- `index.html` وصفحات `pages/` للموقع العام والحسابات.
- `pages/student/` لمساحة الطالب.
- `pages/teacher/` لمساحة المعلم.
- `pages/library.html` كدليل عام للمكتبات.
- `pages/site/` للمعلومات والمساعدة.
- `pages/legal/` لمسودات السياسات.
- `data/` للبيانات العامة التي لا تتضمن أسرارًا.

## المستودعات المستقلة المقترحة

المرفق يقترح فصل المواقع التعليمية عن البوابة، مثل:

| المستودع المقترح | المسؤولية | الحالة في مساحة العمل |
| --- | --- | --- |
| `education-platform` | الحسابات والبوابة والعلوم ومساحات الحساب | الملفات الحالية موجودة هنا محليًا، لكن هذه المساحة لا تحتوي على بيانات Git للتحقق من عنوان المستودع أو دفع التغييرات |
| `english-learning` | الدورات والدروس والواجبات والاختبارات الإنجليزية | لم يُستنسخ أو يُنشأ ضمن هذه المساحة |
| `knowledge-library` | دليل المكتبات المتخصصة | يوجد دليل محلي في `pages/library.html`؛ المستودع المستقل غير متاح |
| مستودعات علوم ومكتبات أخرى | المحتوى المتخصص حسب المجال | لم تُنشأ أو تُحدد عناوينها |

لا تشير بيانات `data/sciences.json` و`data/library.json` إلى مستودعات GitHub تخمينية. تُترك عناوين المستودعات فارغة إلى أن تُنشأ المواقع وتُختبر روابط نشرها. كما أزيلت أعداد الطلاب والدورات وعناوين الكتب التجريبية التي قد تبدو كأنها بيانات منشورة.

## المصادقة المشتركة

استخدام مشروع Firebase واحد لا ينقل جلسة الدخول تلقائيًا بين نطاقات GitHub Pages مختلفة؛ تخزين جلسة Firebase مرتبط بأصل الموقع. يجب اختيار آلية موثوقة لكل نطاق (مثل إعادة تسجيل الدخول عبر Firebase، أو حل هوية اتحادي مناسب) وعدم تمرير رموز جلسات سرية في روابط عادية. يجب نشر قواعد Firestore وStorage بحيث تتحقق من UID وملكية الدورة والدور، وألا تعتمد الحماية على إخفاء صفحات الواجهة.

## ترتيب الإكمال

1. اعتماد عناوين المستودعات الفعلية وإعداد كل مستودع ونطاق نشر.
2. توصيل الدورات والتسجيلات ومحتوى المكتبة بخدمات وقواعد أمان موثوقة.
3. بناء عمليات المعلم والطالب على البيانات الفعلية، بما فيها الواجبات والتصحيح والنتائج.
4. تفعيل الدفع أو رفع الملفات أو الشهادات فقط بعد إعداد الخدمات الخلفية والتحقق من صلاحياتها.

الصفحات التي تعرض حالة «قيد الإعداد» لا تحفظ محتوى أو تؤكد عملية غير متصلة بالخادم.
