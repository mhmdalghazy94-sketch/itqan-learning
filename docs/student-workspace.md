# واجهة الطالب وتسليم الواجبات

تُنشأ صفحات الطالب من `tools/generate-student-pages.js`. وتستخدم لوحة الطالب وقوائم المقررات والواجبات بيانات العرض الموجودة في `data/student-mock.json`؛ هذه البيانات تجريبية وليست بيانات حساب حقيقية. قائمة `courses` تمثل المقررات المسجل بها الطالب، بينما `availableCourses` أمثلة استكشافية. البحث والتصفية والمفضلة تعمل في الواجهة، وتُحفظ المفضلة محليًا على الجهاز.

يولّد الملف أيضًا مجموعات الدروس والاختبارات والتقارير والجدول والتواصل والمكتبة والمساعد والإنجازات والمشاريع والإعدادات والدعم. الملفات موجودة ومربوطة بقائمة الطالب، لكن تدفقات الدرجات الرسمية والحضور والرسائل والمساعد الذكي والملفات التعليمية والعمل الجماعي تحتاج خدمات خلفية قبل اعتبارها ميزات إنتاجية.

## مسودات الواجبات

يحفظ محرر الواجبات نص المسودة في `localStorage` على الجهاز الحالي فقط. لا يعني ذلك أنها رُفعت إلى المنصة أو تمت مزامنتها، كما أن المرفقات لا تُحفظ كمسودة. يجب ألا تُستخدم هذه الآلية لحفظ معلومات حساسة على جهاز مشترك.

## ميزات محلية تجريبية

- الاختبارات تعرض تدريبًا عامًا غير رسمي فقط، بمؤقت وتنقل وعلامات ومتابعة محلية؛ لا ترسل النتيجة ولا تمنح درجة، ولا تحتوي على مفتاح إجابة. لا تستخدم هذا المسار لتقييم حقيقي.
- التقارير ترسم تقدم مقررات ودرجات من البيانات التجريبية، وتتيح CSV/الطباعة؛ الأهداف تحفظ محليًا فقط. لا توجد بيانات حضور أو GPA رسمية.
- التذكيرات ومهام المشاريع ومسودات التواصل والمفضلة وتقدم القراءة وتفضيلات العرض وتخصيص اللوحة تحفظ في المتصفح الحالي فقط.
- عناصر المكتبة عناوين تجريبية لا توفر ملفات أو تنزيلات. المساعد ينشئ قالبًا ثابتًا للمذاكرة ولا يستدعي نموذجًا أو يقدم إجابات معرفية.
- الدروس ومشغلات الوسائط والتعاون والرسائل وملاحظات المعلم والدعم والتصدير/الحذف/مزامنة التطبيقات هياكل واجهة بانتظار خدماتها.

احذف بيانات الموقع المحلية من إعدادات المتصفح عند استخدام جهاز مشترك. لا تُخزن كلمات مرور أو إجابات اختبارات رسمية أو معلومات صحية/شخصية في هذا التخزين المحلي.

## متطلبات ربط الاختبارات والبيانات

الاختبار الرسمي يجب أن يبدأ بجلسة خادمية تتحقق من المستخدم والمحاولات والصلاحية والوقت؛ وتُحفظ الإجابات ويُستعاد وضعها من الخادم. لا ترسل مفاتيح الإجابات إلى العميل قبل سياسة الإفراج عنها. نقاط API والمسارات والحالة الزمنية يجب أن تكون سلطوية على الخادم، مع منع إعادة التسليم أو تمديد الوقت من المتصفح. وضع التدريب في الواجهة لا يفي بهذه المتطلبات ولا يصدر درجات.

تحتاج التقارير الرسمية إلى مصدر درجات وحضور وتقدم موثوق ومصرح به. لا تعتبر بيانات JSON التجريبية كشف درجات. ينبغي أن تقيّد APIs كل استعلام بالمستخدم والمقرر وتصدر فقط الحقول التي يحق للطالب رؤيتها. اعتمد تصدير التقارير في الخادم عند احتوائه على بيانات شخصية أو درجات رسمية.

التواصل والمشاريع والمساعد الذكي والمكتبة تحتاج بدورها إلى صلاحيات خادمية، ومكافحة إساءة ورسائل مزعجة، واحترام حقوق الموارد. لا تعرض بيانات زملاء أو لوحة ترتيب شخصية. إذا رُبط مساعد توليدي، فاجعل سياسة الخصوصية والمصادر وحدود المساعدة الأكاديمية واضحة، ولا ترسل بيانات الطالب دون موافقة وسياسة صريحة.

## تفعيل التسليم الخادمي

واجهة التسليم مغلقة افتراضيًا: لا تعرض نجاحًا محليًا ولا تنشئ إيصالًا بنفسها. لتفعيلها، وفّر نقطتي API موثقتين بالمستخدم:

- `POST /api/student/assignments/{assignmentId}/submissions` يستقبل `multipart/form-data` يحتوي على `answer` وملفات `files` الاختيارية. لا بد أن يتحقق الخادم من هوية الطالب وحقه في المقرر والموعد النهائي، وأن يحفظ الإجابة والمرفقات قبل الرد بـ `201` وجسم مثل `{"submissionId":"..."}`.
- `GET /api/student/submissions/{submissionId}` يعيد سجلًا يملكه المستخدم الحالي فقط، مثل `{"id":"...","status":"submitted","submittedAt":"..."}` بعد التحقق من اكتمال الحفظ. تعرض صفحة التأكيد إيصالًا فقط عندما يتطابق المعرّف وتكون الحالة `submitted`.

عند استخدام Firebase، نفّذ الكتابة من Cloud Function أو API موثوق بعد التحقق من Firebase Auth؛ لا تثق بمعرّف الطالب أو صلاحياته المرسلة من المتصفح. تحقّق من نوع الملف وحجمه على الخادم أيضًا، وقيّد قراءة وكتابة Firestore وStorage بملكية الطالب. إذا استخدمت جلسات ملفات تعريف الارتباط، فعّل حماية CSRF وخصائص `Secure` و`HttpOnly` و`SameSite` المناسبة. أعد خطأ HTTP واضحًا إذا فشل أي حفظ، ولا تُصدر رقم تسليم قبل نجاحه. لا يحتوي المستودع حاليًا على إعداد Firebase أو خادم لهذه النقطتين؛ لذلك يفشل التسليم بوضوح حتى يتم ربطهما.
