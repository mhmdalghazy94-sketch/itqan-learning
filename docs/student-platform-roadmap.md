# تحسين واجهة الطالب وخطة الربط

## التحسينات المشتركة المفعلة

- مولّد `tools/generate-student-pages.js` ينشئ رأسًا وقائمة موحدة ومسار تنقل لكل صفحة طالب. القائمة الأساسية تحتوي 13 قسمًا؛ الروابط الأقل استخدامًا متاحة كرابط ثانوي.
- القائمة قابلة للطي في الشاشات الصغيرة، وتغلق بعد التنقل. يحتفظ رابط الصفحة الحالية بحالة `aria-current`.
- `src/js/student/shell.js` يحمل أدوات المظهر فقط؛ تُحمّل `workspace.js` ديناميكيًا للصفحات التي تحتاج بيانات، و`features.js` عند الحاجة إلى لوحة الطالب أو صفحات ميزاتها.
- تتضمن الواجهة مظهرًا داكنًا وفاتحًا، مؤشرات تركيز، أهداف لمس، حالات تحميل وخطأ وفراغ في المواضع المدعومة، ومسار تنقل، وتقليل حركة واحترام `prefers-reduced-motion`.
- يمكن تخصيص أقسام لوحة التحكم وتذكر الترتيب والإخفاء محليًا. تفضيلات المظهر وإمكانية الوصول تظل محلية ما لم يُضف مخزن حساب موثوق.
- صفحات التدريبات والتقارير والمراسلات والمكتبة توضح صراحةً متى تكون البيانات تجريبية أو محلية. لا تعرض درجات أو رسائل أو إيصالات خادمية مزيفة.

## ما لا يزال بحاجة إلى استكمال

يستخدم الموقع الآن Firebase Web SDK modular عبر CDN في `src/js/services/firebase.js`، بإعداد Web App الذي زوّد به المستخدم، وخدمتي Authentication وCloud Firestore. لا يُحمّل Analytics حاليًا. إعداد عميل الويب ليس سرًا؛ لا تضع مفتاح Service Account أو أسرار الخادم في JavaScript العام.

### صفحة الترحيب والجلسة

- الصفحة العامة هي `pages/welcome.html`. تعرض المجالات والمكتبة وروابط الزائر، ولا تقرأ الدور من `localStorage` أو من معامل URL.
- لعرض تجربة الطالب أو المعلم، تقرأ الصفحة حالة Firebase Authentication ثم تجلب `users/{uid}` من Firestore. لا تُقرأ الأدوار من `localStorage` أو معاملات URL.
- تمنع الصفحة غير المفعّل بريده أو المعلم الذي طلبه `pending` من ظهور روابط لوحة التحكم. هذا تنظيم تجربة فقط وليس حاجز صلاحيات؛ يجب فرض الوصول في كل API وقواعد Firebase/Storage.
- صفحات المعلم الحالية ملفات فارغة؛ يلزم تنفيذها قبل أن تصبح روابط لوحة المعلم وإدارتها وجهات قابلة للاستخدام.

### صفحات الحساب والتسجيل

- صفحات الحساب متاحة في `pages/register.html` و`pages/student-register.html` و`pages/teacher-register.html` و`pages/login.html`، مع استعادة كلمة المرور والتحقق من البريد وحالات انتظار المعلم والوصول غير المصرح.
- يستخدم `src/js/services/auth.service.js` Firebase Auth لإنشاء الحساب وتسجيل الدخول واستعادة كلمة المرور والتحقق من البريد. يُحفظ ملف الحساب في `users/{uid}`، وتُخزن كلمة المرور فقط لدى Firebase Auth.
- التسجيل ينشئ الطلاب بحالة `active` (لكن تسجيل الدخول يتطلب التحقق من البريد)، وينشئ المعلمين بحالة `pending`. قواعد `firestore.rules` تسمح بهذه القيم فقط وتمنع تعديل `role` أو `status` من المستخدم.
- يُحذف حساب Authentication حديث الإنشاء إذا فشل حفظ ملف Firestore. إذا فشل إرسال التحقق بعد حفظ الملف، يبقى الحساب ويعرض النموذج رسالة دقيقة لإعادة الإرسال.
- رابط إعادة تعيين Firebase `oobCode` يُحذف من شريط العنوان بعد قراءته ويُستهلك عبر Firebase Auth. قالب البريد الافتراضي لـ Firebase قد يعرض معالج Firebase المستضاف؛ لاستخدم صفحة `reset-password.html` المخصصة، اضبط قالب إجراء البريد/رابط المعالج في Firebase ليوجه إلى النطاق المنشور واختبر تدفق الرابط فعليًا.
- أمان الأدوار يعتمد على نشر `firestore.rules`؛ وجود قواعد في المستودع وحده لا يفعّلها في Firebase. لا تمنح المعلم صلاحيات التدريس إلا عبر تعديل موثوق في Firebase Console أو Admin SDK/خادم بعد المراجعة؛ لا توسع قواعد العميل لتسمح للمستخدم بتعديل حالته.
- يجب تفعيل Email/Password في Firebase Authentication وإنشاء Cloud Firestore في المشروع، وإضافة نطاق التطوير/الإنتاج إلى Authorized domains. لا تُخزن كلمات المرور أو رموز الاستعادة في Firestore أو `localStorage`.
- نصوص الموافقة في النموذج لا تستبدل نشر شروط استخدام وسياسة خصوصية فعليتين؛ يجب إضافة روابط الوثائق القانونية قبل الإطلاق.

الربط المقترح عند بدء مرحلة الخادم:

1. تفعيل Email/Password وإنشاء Firestore، ثم نشر `firestore.rules` واختبار التسجيل والقراءة والتعديلات غير المصرح بها على مشروع التطوير.
2. تعريف قواعد Firestore وStorage لكل البيانات اللاحقة. يجب رفض الوصول افتراضيًا، والتحقق من `request.auth.uid` والملكية والتحقق من الحقول والأنواع والأحجام.
3. وضع إجراءات الدرجات والمواعيد ومحاولات الاختبار والتسليم والصلاحيات في Cloud Functions أو API موثوق. قواعد العميل وحدها لا تكفي لاعتماد وقت الاختبار أو الدرجة أو إيصال التسليم.
4. بناء خدمة جلسة/ملف موحدة ذات معالجة صريحة لحالة تسجيل الدخول وانتهاء الصلاحية، ثم ترحيل ميزة واحدة في كل مرحلة مع اختبارات قواعد الوصول.
5. حفظ تفضيلات واجهة غير حساسة فقط للمستخدم بعد المصادقة. أبقِ بيانات الاختبارات الرسمية والدرجات والمرفقات الخاصة خارج `localStorage`.

## نموذج بيانات أولي حسب الوظائف الفعلية

استخدم معرف Firebase Auth UID في الملكية، ولا تكرر بيانات الملف الشخصي داخل كل وثيقة. أسماء المجموعات المقترحة أدناه نقطة بداية وليست التزامًا بإنشاء كل مجموعة.

| المسار المقترح | الحقول الأساسية | صلاحية الطالب |
| --- | --- | --- |
| `users/{uid}` | `displayName`, `role`, `createdAt` | قراءة/تعديل حقول الملف المسموح بها لذاته فقط؛ الدور لا يحرره العميل |
| `student_profiles/{uid}` | `level`, `locale`, `preferences` | قراءة وتعديل تفضيلاته غير الحساسة فقط |
| `courses/{courseId}` | `title`, `visibility`, `instructorId` | قراءة المقرر المنشور فقط |
| `enrollments/{uid_courseId}` | `studentId`, `courseId`, `status`, `createdAt` | قراءة التسجيلات التي يكون الطالب مالكها؛ الإنشاء عبر مسار موثوق |
| `lessons/{lessonId}` | `courseId`, `moduleId`, `contentRef`, `order` | قراءة محتوى مقرر مسجل فيه فقط |
| `lesson_progress/{uid_lessonId}` | `studentId`, `lessonId`, `position`, `completedAt` | قراءة/تعديل تقدم الطالب نفسه مع التحقق من حدود القيم |
| `assignments/{assignmentId}` | `courseId`, `title`, `dueAt`, `constraints` | قراءة واجب مقرر مسجل فيه؛ لا صلاحية كتابة مفتوحة |
| `assignment_submissions/{submissionId}` | `studentId`, `assignmentId`, `storagePaths`, `submittedAt`, `status` | قراءة سجلاته فقط؛ الإنشاء والتحقق الخادمي |
| `assignment_grades/{gradeId}` | `studentId`, `assignmentId`, `score`, `feedback`, `releasedAt` | قراءة عند الإفراج فقط؛ الكتابة للمعلم/الخادم |
| `exams/{examId}` | `courseId`, `schedule`, `duration`, `attemptPolicy` | قراءة بيانات التعليمات المنشورة دون answer keys |
| `exam_attempts/{attemptId}` | `studentId`, `examId`, `startedAt`, `expiresAt`, `status` | القراءة عبر جلسة موثقة؛ بدء المحاولة والحفظ والإغلاق عبر API موثوق |
| `student_answers/{answerId}` | `attemptId`, `questionId`, `answer`, `updatedAt` | لا قراءة متقاطعة بين الطلاب؛ لا تخزن مفتاح الإجابة هنا |
| `exam_results/{resultId}` | `studentId`, `attemptId`, `score`, `releasedAt` | قراءة المالك بعد اعتماد وإفراج النتيجة |
| `attendance_records/{recordId}` | `studentId`, `classId`, `status`, `recordedAt` | قراءة السجل الخاص؛ تعديل عبر موظف مخول أو طلب مراجعة |
| `student_notes/{noteId}` | `studentId`, `courseId`, `lessonId`, `body`, `updatedAt` | قراءة وكتابة المالك |
| `student_bookmarks/{bookmarkId}` | `studentId`, `resourceId`, `createdAt` | قراءة وكتابة المالك |
| `study_sessions/{sessionId}` | `studentId`, `courseId`, `startedAt`, `duration` | قراءة وكتابة المالك مع حد معدل مناسب |
| `study_goals/{goalId}` | `studentId`, `title`, `dueAt`, `status` | قراءة وكتابة المالك |
| `notifications/{notificationId}` | `recipientId`, `type`, `readAt`, `createdAt` | قراءة وتحديث حالة القراءة للمتلقي فقط؛ الإنشاء خادمي |
| `conversations/{conversationId}` | `participantIds`, `createdAt` | قراءة المشاركين فقط؛ التحقق الخادمي من قائمة المشاركين |
| `messages/{messageId}` | `conversationId`, `senderId`, `body`, `createdAt` | قراءة أعضاء المحادثة؛ الكتابة مع مكافحة إساءة وحدود معدل |
| `projects/{projectId}` | `ownerId`, `memberIds`, `title`, `status` | قراءة الأعضاء فقط؛ صلاحيات منفصلة للانضمام وتعديل المشروع |
| `project_submissions/{submissionId}` | `projectId`, `studentId`, `storagePaths`, `submittedAt` | ملكية وإفراج المراجعة يتحقق منهما الخادم |
| `support_tickets/{ticketId}` | `ownerId`, `status`, `subject`, `createdAt` | قراءة المالك وفريق الدعم المصرح؛ لا ثقة بدور يرسله العميل |
| `user_preferences/{uid}` | `theme`, `fontScale`, `reducedMotion` | المالك فقط، مع قائمة حقول مسموحة |
| `audit_logs/{logId}` | `actorId`, `action`, `target`, `createdAt` | لا قراءة/كتابة للطالب؛ إنشاء خادمي فقط |

عند استخدام Firebase Storage، اجعل المسارات متضمنة UID (مثل `students/{uid}/submissions/{submissionId}/{fileId}`)، لكن لا تعتبر شكل المسار إثباتًا للملكية وحده. افحص العضوية وحالة الواجب والموعد ونوع الملف وحجمه في الخادم والقواعد، ولا تسمح برفع عام.

## مراحل تسليم قابلة للاختبار

1. **الأساس:** مصادقة الطالب، قائمة مختصرة، تنقل جوال، حالات تحميل/فراغ/خطأ، إعدادات وصول وتفضيل آمنة، واختبارات صلاحيات.
2. **التعلم:** مصدر مقررات موثوق، تسجيلات، دروس ووسائط مرخصة، تقدم مزامن، وملاحظات ومفضلة.
3. **التقييم:** مسودات وتسليم واجبات خادمي، ثم جلسات اختبار خادمية ومؤقت سلطوي وحفظ واستعادة ونتائج مؤجلة الإفراج.
4. **المتابعة:** درجات وتقارير وحضور وأهداف وشهادات من مصادر مصرح بها؛ اختبر عزل بيانات مستخدمين اثنين.
5. **الأدوات:** بطاقات وتقويم ومكتبة ومشاريع مع حدود التخزين والترخيص وإتاحة الوصول.
6. **التواصل والمساعد:** رسائل ومناقشات ومكافحة إساءة، ثم تكامل مساعد بموافقة واضحة ومصدر وسياسة خصوصية مناسبة.
7. **الإطلاق:** اختبارات قواعد Firebase السلبية والإيجابية، لوحة أخطاء وأداء لا تسجل محتوى حساسًا، تدقيق الوصول، وقياس الأداء على الجوال.

لا تنفّذ كل الوحدات دفعة واحدة؛ لا تنتقل بميزة إلى بيانات إنتاجية حتى توجد لها صلاحيات مختبرة، وحالات فشل قابلة للفهم، واختبارات تغطي مستخدمًا لا يملك المورد.
